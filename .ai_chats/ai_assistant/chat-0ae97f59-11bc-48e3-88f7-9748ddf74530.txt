# Changing Committer Name and Email of a Local Commit

You can change the committer information of a local commit using Git commands. Here are the most common scenarios:

## 1. Change the Most Recent Commit

If you only want to change the **author** of the last commit:

```bash
git commit --amend --author="New Name <new.email@example.com>" --no-edit
```

To also update the **committer** (not just the author), set the environment variables:

```bash
GIT_COMMITTER_NAME="New Name" GIT_COMMITTER_EMAIL="new.email@example.com" git commit --amend --author="New Name <new.email@example.com>" --no-edit
```

## 2. Change Multiple Local Commits

For rewriting several commits, use an interactive rebase:

```bash
git rebase -i HEAD~N
```

Replace `N` with the number of commits to go back. In the editor, mark the commits you want to change with `edit` (instead of `pick`). Then for each stopped commit run:

```bash
GIT_COMMITTER_NAME="New Name" GIT_COMMITTER_EMAIL="new.email@example.com" \
  git commit --amend --author="New Name <new.email@example.com>" --no-edit
git rebase --continue
```

## 3. Change All Commits in the Repository

Use `git filter-repo` (recommended over the deprecated `filter-branch`):

```bash
git filter-repo --commit-callback '
  commit.author_name = b"New Name"
  commit.author_email = b"new.email@example.com"
  commit.committer_name = b"New Name"
  commit.committer_email = b"new.email@example.com"
'
```

## 4. Update Git Config So Future Commits Are Correct

To avoid this issue going forward:

```bash
# For this repo only
git config user.name "New Name"
git config user.email "new.email@example.com"

# Or globally
git config --global user.name "New Name"
git config --global user.email "new.email@example.com"
```

## Doing It in IntelliJ IDEA

- **Amend the last commit**: Open the **Commit** tool window (`⌘0` on macOS / `Alt+0` on Windows/Linux), check **Amend** before committing.
- **Change Git user for the project**: `Git` → `Manage Remotes` is for remotes; for user identity go to **Settings/Preferences → Version Control → Git → Configure** or set it via the terminal.
- **Interactive rebase**: Open the **Git** tool window → **Log** tab → right-click a commit → **Interactively Rebase from Here…**

> ⚠️ **Warning**: If any of these commits were already pushed to a shared branch, rewriting history will require a force-push (`git push --force-with-lease`) and may disrupt collaborators.

# Changing the First (Root) Commit's Author/Committer

## Why Your Command Failed

Two issues with `git rebase -i HEAD~10`:

1. **PowerShell quoting**: The trailing `'` may have been interpreted oddly. But more importantly:
2. **Not enough commits**: `HEAD~10` means "10 commits before HEAD". If your repo has fewer than 11 commits, this fails. Also, you **cannot** rebase the very first (root) commit this way, because it has no parent.

## Solution: Use `--root`

To include the very first commit in an interactive rebase, use the `--root` flag:

```powershell
git rebase -i --root
```

This opens an editor listing **all** commits, including the first one. Steps:

1. Change `pick` to `edit` for the first commit (and any others you want to modify).
2. Save and close the editor.
3. When the rebase stops at that commit, run:

```powershell
$env:GIT_COMMITTER_NAME="New Name"
$env:GIT_COMMITTER_EMAIL="new.email@example.com"
git commit --amend --author="New Name <new.email@example.com>" --no-edit
git rebase --continue
```

4. After the rebase finishes, unset the variables (optional):

```powershell
Remove-Item Env:GIT_COMMITTER_NAME
Remove-Item Env:GIT_COMMITTER_EMAIL
```

## Alternative: If It's Literally Only One Commit in the Repo

If your repository contains just a single commit, you can simply amend it:

```powershell
$env:GIT_COMMITTER_NAME="New Name"
$env:GIT_COMMITTER_EMAIL="new.email@example.com"
git commit --amend --author="New Name <new.email@example.com>" --no-edit
```

## Doing It in IntelliJ IDEA

- Open the **Git** tool window (`Alt+9`) → **Log** tab.
- Right-click the very first commit → **Interactively Rebase from Here…** (this works on the root commit in recent IDE versions).
- Mark it as **Edit**, proceed, and amend with the new author.

> ⚠️ If these commits were already pushed, you'll need `git push --force-with-lease` afterward, and collaborators will need to re-sync.
