---

## Why `.idea/workspace.xml` Still Appears in the VCS Changelist

The most common reason is that **`.idea/workspace.xml` was already committed to the Git repository before the `.gitignore` rule was added**. Once a file is tracked by Git, adding it to `.gitignore` has **no effect** — Git continues to track changes to it.

### How Git's `.gitignore` Works

`.gitignore` only prevents **untracked** files from being tracked. It does **not** automatically un-track files that are already in Git's index (i.e., already committed).

---

## How to Fix It

You need to **remove the file from Git's index** (stop tracking it) without deleting the actual file from disk:

```bash
git rm --cached .idea/workspace.xml
```

Then commit the removal:

```bash
git commit -m "Stop tracking .idea/workspace.xml"
```

After this, Git will respect the `.gitignore` rule and stop showing changes to that file in the changelist.

---

## Summary

| Situation | `.gitignore` Effect |
|---|---|
| File was **never committed** | ✅ Git ignores it |
| File **was already committed** | ❌ Git still tracks it — `.gitignore` has no effect |

The fix is `git rm --cached .idea/workspace.xml` to remove it from the index while keeping it on disk.
