     Plan: GitHub scraper for Kotlin/KEEP and kubernetes/enhancements

     Context

     This is a TU Delft CSE3000 research project (RQ3) doing a comparative study
      of two
     ecosystem proposal processes:

     - KEEP — Kotlin Evolution and Enhancement Process. Hosted at Kotlin/KEEP.
     Proposals are markdown files merged via PR, but discussion happens 
     primarily
     on the repo's GitHub Discussions tab (GraphQL-only API).
     - KEP — Kubernetes Enhancement Proposals. Hosted at
     kubernetes/enhancements.
     Each proposal is a directory under keps/ containing a kep.yaml, README, and
     PRR docs, with a tracking issue and discussion spread across multiple PRs 
     and
     issues (REST works fine).

     The goal of this scraper is to download everything that might be needed for
     both repos in one pass, persist it locally for offline processing, and
     support
     incremental refresh via a Gradle task without re-downloading what hasn't
     changed (since the GitHub API rate limit is a concern). The final analysis
     target is a MySQL database with a schema TBD, so the scraper output should
     be structured but loosely-coupled to any specific schema (JSON-on-disk is
     the
     right level of abstraction). The :rq3 analysis module is out of scope here.

     The project is currently a clean Gradle multi-module scaffold (Kotlin
     2.3.20, JVM
     toolchain 25). All src/main/kotlin directories are empty. Existing version
     catalog already provides kotlinx-coroutines 1.10.2,
     kotlinx-serialization-json
     1.9.0, and kotlinx-datetime 0.7.1.

     Approach

     Hybrid HTTP layer — Ktor Client for REST + a hand-written GraphQL escape
     hatch in the same Ktor stack. No Apollo, no second HTTP framework. Reasons:

     - For ~500 proposals total, REST + ETags is simpler, gives self-documenting
     JSON-on-disk artifacts (good for a thesis appendix), and supports cheap
     incremental reruns via If-None-Match.
     - KEEP's GitHub Discussions tab forces some GraphQL. We add a single
     runGraphQL(query, variables) method to the Ktor client and write the few
     queries we need by hand (repository.discussions, discussion.comments,
     discussion.comments.replies, reactions). Apollo's codegen + schema tooling
     is overkill for ~3-4 queries.
     - KEP's discussions are issue/PR comments → pure REST.

     Two-tier disk persistence under data/ (gitignored):

     data/
       cache/
         raw/<repo>/<endpoint>/<id>.json     # verbatim API responses
         etags.json                          # url -> etag
         last-sync.json                      # endpoint -> max(updated_at)
       normalized/
         keep-proposals.jsonl, keep-comments.jsonl, keep-reviews.jsonl,
         keep-discussions.jsonl, keep-discussion-comments.jsonl,
         kep-proposals.jsonl, kep-comments.jsonl, kep-reviews.jsonl,
         kep-yaml.jsonl, users.jsonl, reactions.jsonl, labels.jsonl,
         timeline-events.jsonl
       manifests/<run-timestamp>.json        # rate-limit usage, counts, commit
     SHA

     JSONL is later loaded into MySQL with a small bulk-insert step once the
     schema
     is finalized. Skip SQLite/SQLDelight — adds schema-migration burden with no
     queryability gain at this volume.

     Module layout

     :utils (domain-agnostic, package dev.cse3000.gh)

     - client/GithubClient.kt — Ktor wrapper. Suspend functions per endpoint:
     listPullRequests, getPullRequest, listIssueComments, listReviewComments,
     listReviews, listReactions, listTimelineEvents, listChecks, getContent,
     runGraphQL. Uses ktor-client-cio + content-negotiation + kotlinx-json.
     - client/RateLimiter.kt — Semaphore(8) for concurrency cap + adaptive
     throttle
     reading X-RateLimit-Remaining / X-RateLimit-Reset; suspends until reset
     when remaining drops below a configurable floor (default 100).
     - client/RetryPolicy.kt — handles 403 + Retry-After (secondary rate limit)
     and 5xx with exponential backoff; treats 304 Not Modified as a cache hit.
     - client/Paginator.kt — Flow<JsonElement> over Link header pagination.
     - cache/EtagStore.kt — load/save etags.json, attach If-None-Match per URL.
     - cache/RawCache.kt — write/read JSON keyed by URL → file path.
     - cache/SyncCursor.kt — load/save last-sync.json per endpoint key.
     - io/JsonlWriter.kt — append-only JSONL output.
     - io/Env.kt — read GITHUB_TOKEN (fail fast if missing).
     - io/RunManifest.kt — emit run-summary JSON at end of each scrape.
     - model/ — generic GitHub DTOs (GhUser, GhIssue, GhPullRequest,
     GhComment, GhReview, GhReaction, GhLabel, GhTimelineEvent,
     GhCheckRun, GhDiscussion, GhDiscussionComment, RateLimitInfo).
     These map directly to GitHub responses and are shared by both scrapers.
     - scraper/ProposalScraper.kt — interface: suspend fun run(); fun 
     discover(): Flow<ProposalRef>.

     :utils/build.gradle.kts already has the kotlinx bundle. Add Ktor + plugin:
     alias(libs.plugins.kotlinPluginSerialization) and Ktor dependencies.

     :keep (package dev.cse3000.keep)

     - model/KeepProposal.kt, model/KeepProposalRef.kt, model/KeepDiscussion.kt
     - scrape/KeepProposalDiscovery.kt — list PRs that touch proposals/*.md;
     resolve linked issue via the PR's "closing issues" GraphQL field with REST
     body-parse fallback (Fixes #N).
     - scrape/KeepDiscussionsDiscovery.kt — GraphQL query
     repository(owner:"Kotlin", name:"KEEP") { discussions(first:100, 
     after:$cursor) { ... } } to enumerate discussions, then fetch comments +
     replies + reactions.
     - scrape/KeepScraper.kt — orchestrator wired into Main.kt CLI.
     - Main.kt — CLI entry (Gradle application plugin). Subcommands full and
     update (incremental).

     :kep (package dev.cse3000.kep)

     - model/KepProposal.kt, model/KepYaml.kt, model/KepProposalRef.kt
     - parse/KepYamlParser.kt — uses kaml (kotlinx-serialization-yaml port)
     for kep.yaml.
     - scrape/KepDiscovery.kt — walks keps/ via the contents API, parses each
     kep.yaml, resolves tracking issue + linked PRs from the yaml metadata.
     - scrape/KepScraper.kt — orchestrator wired into Main.kt CLI.

     :keep and :kep both need alias(libs.plugins.kotlinPluginSerialization)
     applied (compiler plugin, doesn't transit through
     implementation(projects.utils)).

     Auth, rate-limit, incremental refresh

     - GITHUB_TOKEN env var → Authorization: Bearer <token> (gives 5000 req/hr
     REST,
     5000 points/hr GraphQL).
     - Concurrency: Semaphore(8) ceiling on in-flight requests.
     - After every response: read X-RateLimit-Remaining; if < 100, suspend until
     X-RateLimit-Reset.
     - Conditional GET: EtagStore attaches If-None-Match; 304 → return cached
     body
     for free (does not consume quota).
     - Incremental: since query param on issues/comments lists, persisted per
     endpoint in last-sync.json. Combined with ETags, a refresh after a quiet
     day
     costs only a few hundred requests.

     Gradle wiring

     - :keep and :kep apply the Gradle application plugin so each can be run
     via ./gradlew :keep:run and ./gradlew :kep:run.
     - Add a top-level Gradle task updateScrapedData that depends on
     :keep:run --args="update" and :kep:run --args="update". This is the
     one-command incremental refresh the user asked for.
     - Add a separate fullScrape task for the initial backfill.
     - Both tasks fail fast if GITHUB_TOKEN is unset.

● Done. Build is green across all modules. Here's what was put in place:

  Library choice: Hybrid HTTP via Ktor 3 (ktor-client-cio + content-negotiation
  + kotlinx-serialization). REST for almost everything, hand-written GraphQL
  strings via the same client only where required (Kotlin/KEEP's Discussions
  tab).

  :utils shared infrastructure (dev.cse3000.gh.*):
  - client/GithubClient.kt — Ktor wrapper. Auto-attaches Authorization: Bearer,
  If-None-Match (ETag), retries on 403/429/5xx with Retry-After honoring,
  paginates Link headers as a Flow<JsonElement>, exposes a runGraphQL method.
  - client/RateLimiter.kt — Semaphore(8) for concurrency cap + adaptive throttle
   reading X-RateLimit-Remaining / Reset.
  - cache/EtagStore.kt, RawCache.kt, SyncCursor.kt — disk-backed
  conditional-request and incremental state.
  - io/JsonlSink.kt — append-only JSONL writers per stream, auto-stamps
  _scraped_at and _repo metadata on every line.
  - io/RunManifest.kt — per-run summary file with request counts and 304 hit
  rate.
  - io/ScrapeContext.kt — wires the client + cache + sink + cursor from
  GITHUB_TOKEN env var and data/.
  - scraper/IssueAndPrCollector.kt — domain-agnostic logic that fetches issues,
  PRs, comments, reviews, files, commits, and timeline events. Both scrapers
  reuse it.

  :keep — KeepScraper runs the shared collector plus KeepDiscussionsCollector,
  which walks GitHub Discussions via three GraphQL queries (list discussions →
  list comments per discussion → list replies per comment) so nothing is
  truncated by the 50/100 connection caps.

  :kep — KepScraper runs the shared collector plus KepDiscovery, which fetches
  the default-branch git tree (one request, recursive=1), filters for
  keps/**/kep.yaml, and parses each via KepYamlParser (kaml's parseToYamlNode →
  loose JsonElement, all scalars stringified to keep things schema-agnostic).

  Persistence layout under data/ (gitignored):
  data/cache/raw/<sha1-shard>/<sha1>.json   verbatim API responses
  (304-cacheable)
  data/cache/etags.json                     URL → ETag
  data/cache/last-sync.json                 endpoint → max(updated_at)
  data/normalized/*.jsonl                   one stream per entity type
  data/manifests/<repo>-<mode>-<ts>.json    per-run summary

  Gradle wiring — root build.gradle.kts adds fullScrape and updateScrapedData
  tasks; both fan out to :keep:run and :kep:run and pass full or update as args.
   Default ./gradlew :keep:run runs an incremental update.

  To run:
  $env:GITHUB_TOKEN="ghp_..."
  ./gradlew.bat fullScrape          # initial backfill
  ./gradlew.bat updateScrapedData   # cheap incremental refresh
  ./gradlew.bat :keep:run -Pargs="full"   # one-off override

  Caveats worth knowing before first run:
  - Ktor 3.0.3 and kaml 0.65.0 are pinned in libs.versions.toml; bump if Maven
  Central has newer compatible versions.

  - ETag store + sync cursor are persisted only at end of run. If you Ctrl-C
